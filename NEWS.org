** v0.9.6 (2026-11-07)

A repair release: the documentation builds again, so `maak deploy` - the second
half of the pipeline - finishes where it used to stop at its first step.

*** Fixes

- `documenta api` could not finish, for three reasons at once.  Guile reads a
  module's documentation from =;;; Commentary:= to =;;; Code:=, and the modules
  had no code marker, so the whole source counted as documentation and
  documenta parsed code as Texinfo; every documented module carries the marker
  now.
- A docstring holding =user:pass@host= or =~@[= stopped the Texinfo parser at
  the =@=, because that is a command character.  Those =@= are doubled, which is
  how a literal one is written, and the rendered pages carry a single =@=
  again.
- documenta refuses an exported name its module never defines, and found two
  left behind by renames: =migration-files= in =(mutastructura mutastructura)=
  and =migration-exception= in =(mutastructura persistence util)=.  Both are
  gone, and no module selected either.

** v0.9.5 (2026-11-07)

A housekeeping release: the project is MIT licensed, the repository lives at
GitHub, and the pipeline runs on GitHub Actions instead of Woodpecker.

*** Changed

- Mutastructura is licensed under the MIT License, where it was
  AGPL-3.0-or-later.  =COPYING= became =LICENSE=, every source file carries
  =SPDX-License-Identifier: MIT=, and the documentation and examples are MIT
  too rather than FDL-1.3, so one licence covers the tree.
- The sources are tracked at =https://github.com/jjba23/mutastructura= now that
  Codeberg is archived, and the README, the container label and the Arch,
  Debian and openSUSE recipes point there.
- The Nix dev shell carries =guile-veritas= 1.4.0, pinned as a flake input, and
  exports =GUILE_DBD_PATH=, so the suite runs in the shell without Guix.

*** Added

- Continuous integration on GitHub Actions.  =.github/workflows/ci.yml= hands
  the =maak-test= and =maak-deploy= tasks to Byggsteg on every push to
  =trunk=, and =.github/workflows/tests.yml= runs the suite in the Nix dev
  shell, validates the JUnit document against =test/veritas/junit.xsd= and
  publishes it as a check with annotations.

*** Fixes

- Three assertions in =test/veritas/unit/core.scm= named the behaviour from
  before repeatable migrations existed: the engine of a SQLite URL as a string
  rather than a symbol, the kind of a ledger entry that records the kind itself,
  and two migrations pending as =pending= rather than as =pending= and
  =repeatable-pending=.  The suite is green again, which is what CI needs.

  needs to say what changed.
