USAGE: mutastructura [COMMAND] [OPTIONS]

COMMANDS:
    migrate
        (default) Apply the migrations that are pending, in order, and record
        each one in the ledger. A migration that fails rolls back the whole run
        where the engine can undo DDL; where it cannot (MySQL commits DDL as it
        runs) the message says so.
    status
        Report the plan and run nothing: every migration's state, what the plan
        adds up to, and the problems it found (a file changed after it was
        applied, a ledger entry whose file has gone). Opens a session that
        writes nothing, so it is safe against a production database.
    validate
        The same plan as status, but exit 1 when the ledger and the migration
        files disagree. Made for CI, where a report nobody reads is not enough.
    rollback
        Undo applied migrations, newest first, using their *.undo.sql scripts.
        With no selection one migration is undone; --steps N undoes N, --to
        VERSION undoes everything above VERSION, and --all walks back as far as
        undo scripts allow, stopping and naming the migration that has none.
        A migration without an undo script, or one marked irreversible with
        -- mutastructura: irreversible, blocks the rollback rather than being
        skipped. --allow-irreversible overrides the directive. With --dry-run
        it reports the undo statements and changes nothing.
    repair
        Bring the ledger back into agreement with the files: forget a row that
        records a failure, and realign the checksum of a file that changed
        after it was applied. With --dry-run it names the rows and writes
        nothing. A checksum realigned by repair is knowingly accepted as is.
    clean
        Drop everything in the current schema, the ledger included. With
        --dry-run it names what it would drop and drops nothing.
    help
        Display this help message and exit.

OPTIONS:
    -h, --help
        Display this help message and exit.
    -d, --database
        The engine you are targeting: sqlite3, postgresql, cockroachdb,
        mysql (or mariadb), plus the aliases each accepts
        (pg, psql, crdb, percona, timescaledb, yugabyte, ...).
    -c, --connection
        A URL, or the driver's own connection string. A URL looks like:
          sqlite3:///var/lib/app.db
          postgresql://alice:secret@db.example.net:5432/appdb
          mysql://alice:secret@127.0.0.1:3306/appdb
        Anything else is taken as the engine's connection string, which is
        guile-dbi's own user:pass:db:tcp:host:port form.
    -m, --migrations
        The path to your migrations directory: *.sql files and their
        *.undo.sql counterparts. A file named *.repeatable.sql runs again
        whenever its contents change; the rest run once, in order.
        Read by every command except clean.
    --placeholder key=value
        Substitute ${key} with value in every migration read during this run.
        Repeat the option (--placeholder a=1 --placeholder b=2) or separate the
        pairs with commas (--placeholder a=1,b=2). A ${...} nobody defined is
        left exactly as it was, so a migration may carry its own template
        syntax in a comment.
    --target VERSION
        Stop at VERSION: the migration whose version is VERSION runs, and so
        does everything below it; anything above is reported as beyond-target.
        A date may be used as a prefix (--target 2026-04-01 covers that day).
    --out-of-order
        Apply a pending migration older than the newest one already applied.
        Such a migration is held back by default, because running it on top of
        a newer schema is how a deploy breaks in a subtle way.
    --to VERSION
        (rollback) Undo everything applied above VERSION and leave VERSION
        applied. Refused as a whole when any migration in that range cannot be
        undone, because skipping one would undo an earlier schema underneath a
        later migration that expects it.
    --steps N
        (rollback) Undo the N newest applied migrations. Refused as a whole for
        the same reason as --to.
    --all
        (rollback) Undo as far back as undo scripts allow: the newest run of
        rollback-able migrations, then stop and name the one that blocked it.
    --allow-irreversible
        (rollback) Undo a migration whose author marked it irreversible with
        the directive comment -- mutastructura: irreversible.
    --dry-run
        Read the plan and the statements of every migration that would run, and
        change nothing: no statement is sent, no ledger row is written, and the
        ledger is not created if it is missing. With clean it reports the drops,
        with repair the rows it would fix, and with rollback the undo
        statements it would run.
    -v, --verbose
        Show each statement in full -- multi-line bodies included -- instead of
        the first line of it. Without this, a run reports its summary and one
        line per statement.
    -r, --resources
        (optional) Path to internal application resources (used for development and installation)
        bundled from ./resources dir

EXIT STATUS:
    0   the command did what it was asked to do (and rollback --all, which
        exits 0 when it undid everything reversible and stopped at a boundary).
    1   it could not: a migration failed, a connection was refused, an option
        was missing, a URL named an engine other than --database, validate
        found a disagreement, or a rollback range held a migration that cannot
        be undone.
